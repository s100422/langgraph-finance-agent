# langgraph-finance-agent

은행 앱을 흉내낸 LangGraph 기반 멀티에이전트 CLI 미니프로젝트. 계좌 개설/조회/이체/해지, 예적금 가입/해지, 대출 신청, 카드 발급/사용/해지, 공과금 자동이체 등록/조회/해지를 자연어로 처리한다.

## 기술 스택

- **LangGraph** — 도메인별 subgraph + 최상위 라우터 그래프
- **LangChain + Gemini** (`langchain_google_genai`) — 자연어 요청을 구조화된 데이터로 추출 (structured output)
- **uv** — 패키지/실행 관리
- Python 3.13+

## 아키텍처

```
사용자 요청 → 최상위 라우터(도메인 분류) → 도메인별 subgraph
                                          (account / product / card / bill_payment)
```

- 각 도메인은 독립된 subgraph로 구현되고, 최상위 그래프엔 `xxx_wrapper` 함수로 연결된다 (도메인마다 State 필드가 다르기 때문).
- 도메인 내부에도 자체 라우터 노드가 하나씩 있어 세부 액션(조회/생성/이체/해지 등)을 분류한다.
- 이체/해지/대출신청/카드해지 같은 민감한 액션은 실행 전 `interrupt()`로 사용자 확인을 받는다. 조회는 확인 없이 즉시 처리된다.
- 신용카드 결제일/대출 상환일/적금 납입일/공과금 출금일은 실시간 스케줄러 없이, 해당 도메인 요청이 들어올 때마다 "지연 정산"하는 방식으로 자동 처리된다 (결제일이 지난 뒤 처음 들어온 요청에서 뒤늦게 정산).
- 멀티턴 대화 맥락은 LangGraph의 `MemorySaver` 체크포인터 + `thread_id=user_id`로 유지된다.

## 파일 구조

```
langgraph-finance-agent/
├── README.md
├── pyproject.toml
├── data/
│   ├── accounts_{user_id}.json       # 유저별 계좌
│   ├── products_{user_id}.json       # 유저별 예적금·대출
│   ├── cards_{user_id}.json          # 유저별 카드
│   ├── bill_payment_{user_id}.json   # 유저별 공과금 자동이체
│   └── account_index.json           # {계좌번호: user_id} 매핑
└── src/langgraph_finance_agent/
    ├── __init__.py       # CLI 진입점(main), interrupt 재개 루프
    ├── llm.py            # Gemini 모델 정의 (light_llm / llm)
    ├── nodes.py          # 최상위 라우터(도메인 분류) + 도메인별 wrapper
    ├── graph.py          # 최상위 StateGraph, MemorySaver 체크포인터
    ├── tools.py          # 공용 유틸(JSON load/save, 지연정산 날짜 계산)
    ├── account/          # 계좌 도메인
    │   ├── nodes.py      # 조회 · 생성 · 이체 · 해지 · 별칭변경
    │   ├── tools.py      # accounts.json IO, 이체 실행 함수
    │   └── graph.py      # 계좌 subgraph
    ├── card/             # 카드 도메인
    │   ├── nodes.py      # 발급 · 조회 · 사용 · 해지 · 별칭변경
    │   ├── tools.py      # cards.json IO, 결제일 지연정산
    │   └── graph.py      # 카드 subgraph
    ├── product/          # 상품 도메인 (예적금 · 대출)
    │   ├── nodes.py      # 가입 · 조회 · 해지 · 대출신청 · 별칭변경
    │   ├── tools.py      # products.json IO, 상품 카탈로그, 지연정산
    │   └── graph.py      # 상품 subgraph
    └── bill_payment/     # 공과금 자동이체 도메인
        ├── nodes.py      # 등록 · 조회 · 해지 · 별칭변경
        ├── tools.py      # bill_payment.json IO, 지연정산
        └── graph.py      # 공과금 subgraph
```

## 멀티유저 데이터 구조

한 파일에 모든 유저 데이터를 넣는 대신 유저별로 파일을 분리한다.

```
data/
  accounts_{user_id}.json      # 유저별 계좌
  products_{user_id}.json      # 유저별 예적금/대출
  cards_{user_id}.json         # 유저별 카드
  bill_payment_{user_id}.json  # 유저별 공과금 자동이체
  account_index.json           # {계좌번호: user_id} — 다른 유저에게 이체할 때 계좌 주인을 찾는 용도
```

계좌번호/카드번호/상품번호 등은 랜덤 생성, 사용자는 별칭(alias)이나 번호 어느 쪽이든 인식된다.

## 실행 방법

`langgraph-finance-agent` 폴더 안에서 실행해야 한다 (`data/`가 실행 위치 기준 상대경로라, 상위 폴더에서 실행하면 엉뚱한 곳에 생성됨).

```bash
uv sync
uv run langgraph-finance-agent
```

`.env`에 다음 값이 필요하다:

```
GEMINI_API_KEY=your-key-here
```

## 계좌 · 이체

| 기능 | 구현 내용 | 사용자 요청 |
|---|---|---|
| 계좌 개설 | 별칭을 받아 새 계좌를 만들고 계좌번호를 발급한다. | "계좌 만들어줘, 별칭은 월급통장." |
| 계좌 조회 | 계좌 목록과 계좌별 잔액·거래내역을 조회한다. 기간(시작일/종료일)을 지정하면 그 기간 거래내역만 보여준다. | "내 계좌 목록과 잔액을 보여줘." / "이번 달 거래내역 보여줘." |
| 계좌이체 | 출금·입금 계좌와 금액을 확인하고 승인(y/n) 후 이체한다. 내 계좌 간 이체와 다른 유저 계좌로의 이체를 모두 지원한다. | "월급통장에서 여윳돈통장으로 10만 원 옮겨줘." |
| 조건부 이체 | 출금 계좌에 남길 금액으로 이체액을 계산하고 승인 후 처리한다. 잔액보다 남길 금액이 크면 거절한다. | "생활비에 40만 원 남기고 나머지를 저축으로 보내줘." |
| 계좌 해지 | 대상 계좌를 확인하고, 잔액이 남아있으면 다른 내 계좌로 옮길지 확인한 뒤 삭제한다. | "여행통장 해지해줘." |
| 계좌 별칭 변경 | 대상 계좌와 새 별칭을 확인하고 저장한다. | "월급통장을 생활비통장으로 바꿔줘." |

## 카드

| 기능 | 구현 내용 | 사용자 요청 |
|---|---|---|
| 카드 발급 | 체크/신용 여부와 연결 계좌를 확인하고 카드번호를 발급한다. 신용카드는 결제일도 함께 받는다(미지정 시 25일). | "체크카드 만들어줘, 월급통장에 연결." |
| 카드 조회 | 카드 목록과 상태를 조회한다. 신용카드는 결제일과 다음 결제 예정액(미정산 사용액)을 함께 보여준다. | "내 카드 목록과 상태를 보여줘." |
| 카드 사용 기록 | 결제 금액을 사용내역에 기록한다. 체크카드는 즉시 연결 계좌에서 출금하고, 신용카드는 결제일에 지연 정산한다. | "데일리카드로 5만 원 결제했어." |
| 카드 해지 | 대상 카드를 확인하고 승인 후 상태만 해지로 바꾼다(사용내역 보존). | "데일리카드 해지해줘." |
| 카드 별칭 변경 | 대상 카드와 새 별칭을 확인하고 저장한다. | "데일리카드를 쇼핑카드로 바꿔줘." |

## 상품 (예·적금·대출)

| 기능 | 구현 내용 | 사용자 요청 |
|---|---|---|
| 예·적금 가입 | 계좌·금액을 확인한 뒤 은행이 미리 정한 상품 목록(번호)을 보여주고 선택받아, 승인 후 가입한다. 적금은 매달 결제일에 자동 납입된다. | "적금 가입하고 싶어, 월급통장에서 매달 5만 원씩." |
| 상품 조회 | 가입한 예·적금·대출 목록과 잔액/진행 상황을 조회한다. | "내 상품 조회해줘." |
| 예·적금 해지 | 대상 상품을 확인하고, 원금+이자를 계산해 승인 후 연결 계좌로 환급한다. | "적금 해지해줘." |
| 대출 신청 | 금액·기간을 확인하고 승인 후 계좌로 입금한다. 매달 결제일에 자동 상환된다. | "대출 신청할게, 300만 원, 12개월." |
| 상품 별칭 변경 | 대상 상품과 새 별칭을 확인하고 저장한다. | "신용대출 별칭을 결혼자금대출로 바꿔줘." |

## 공과금 자동이체

| 기능 | 구현 내용 | 사용자 요청 |
|---|---|---|
| 자동이체 등록 | 공과금 종류·고객확인번호·출금 계좌·출금일을 확인하고 등록한다(출금일 미지정 시 25일). | "전기세 자동이체 등록해줘, 고객번호 1234567890." |
| 자동이체 조회 | 등록된 자동이체 목록과 최근 청구액·출금일·연체 여부를 조회한다. | "내 자동이체 목록 보여줘." |
| 자동이체 해지 | 대상 자동이체를 확인하고 승인 후 상태만 해지로 바꾼다. | "전기세 자동이체 해지해줘." |
| 자동이체 별칭 변경 | 대상 자동이체와 새 별칭을 확인하고 저장한다. | "전기 자동이체 별칭을 본가전기세로 바꿔줘." |

## 구현하지 않은 것

세금·외환 도메인, 실시간 청구 연동(공과금 청구액은 랜덤 시뮬레이션), 입금 기능(테스트 데이터는 JSON 파일 직접 시딩), 트랜잭션/락(원자성 보장) 등은 미니프로젝트 범위 밖으로 제외했다.
